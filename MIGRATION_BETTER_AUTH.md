# Clerk → Better Auth migration

This branch replaces Clerk with [Better Auth](https://better-auth.com) via the
official Convex component (`@convex-dev/better-auth`). The **code** migration is
complete, but it must be **finalized against your own Convex deployment** — this
part could not be done in the automation environment because it needs a live
Convex project (for component codegen), a `BETTER_AUTH_SECRET`, and OAuth
credentials. None of the auth flows have been run yet; treat this as a reviewed
changeset to finalize and test, not a verified drop-in.

## TL;DR to finish it

```bash
# 1. Types: register the component + regenerate _generated (clears the 2 known tsc errors)
npx convex dev            # leave running; it creates the Better Auth tables

# 2. Set Convex env vars (dashboard or `npx convex env set`)
npx convex env set BETTER_AUTH_SECRET "$(openssl rand -base64 32)"
npx convex env set SITE_URL http://localhost:3000        # prod: https://ffsn.ai
# optional social providers:
npx convex env set GOOGLE_CLIENT_ID ...   && npx convex env set GOOGLE_CLIENT_SECRET ...
npx convex env set GITHUB_CLIENT_ID ...   && npx convex env set GITHUB_CLIENT_SECRET ...

# 3. Set Next.js env (.env.local / hosting dashboard)
#    NEXT_PUBLIC_CONVEX_URL       already set (….convex.cloud)
#    NEXT_PUBLIC_CONVEX_SITE_URL  NEW — same deployment, .convex.site domain
echo 'NEXT_PUBLIC_CONVEX_SITE_URL=https://<your-deployment>.convex.site' >> .env.local

# 4. Run and test
npm run dev
```

After step 1, `npx tsc --noEmit` should be **fully clean**. The only two errors
on this branch today are `convex/auth.ts` referencing `components.betterAuth` and
`internal.betterAuthEmail` — both are generated by `convex dev` and cannot exist
until the component is registered.

| Where | Variable | Notes |
|-------|----------|-------|
| Convex | `BETTER_AUTH_SECRET` | Required. `openssl rand -base64 32`. |
| Convex | `SITE_URL` | Base URL of the web app (OAuth/callback base). |
| Convex | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Optional; Google sign-in is inert until both are set. |
| Convex | `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | Optional; same. |
| Convex | `SENDGRID_API_KEY` | Already used; reused for password-reset email. |
| Next | `NEXT_PUBLIC_CONVEX_URL` | Existing (`….convex.cloud`). |
| Next | `NEXT_PUBLIC_CONVEX_SITE_URL` | **New** — the `….convex.site` HTTP-actions URL of the same deployment. |

Remove the old Clerk vars once you're happy: `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`,
`CLERK_SECRET_KEY`, `CLERK_FRONTEND_API_URL`, and any `NEXT_PUBLIC_CLERK_*`.

### OAuth redirect URLs

When creating the Google/GitHub apps, set the authorized redirect URL to your
Convex site URL callback, e.g.:

```
https://<your-deployment>.convex.site/api/auth/callback/google
https://<your-deployment>.convex.site/api/auth/callback/github
```

## What changed

**Backend (`convex/`)**
- `convex.config.ts` (new) — registers the Better Auth component.
- `auth.ts` (new) — `authComponent` + `createAuth` (email/password, Google,
  GitHub, password-reset via SendGrid). Social providers self-enable only when
  their env vars are present. `requireEmailVerification` is **off** for now.
- `auth.config.ts` — Clerk JWT provider replaced with Better Auth's.
- `http.ts` (new) — mounts Better Auth routes on the Convex HTTP endpoint.
- `betterAuthEmail.ts` (new) — SendGrid sender for auth emails (plain text, no
  new template needed).
- `schema.ts` — added a `by_email` index on `users` for reconciliation. The
  `users.clerkId` field is unchanged in name but now holds the Better Auth
  subject id (see below).
- `users.ts` — `createOrUpdateUser` now reconciles legacy accounts (below).

**Frontend (`src/`)**
- `lib/auth-client.ts` (new) — Better Auth browser client with the Convex plugin.
- `lib/auth.tsx` (new) — a Clerk-compatibility shim exporting `useUser`,
  `useAuth`, `UserButton`, `SignedIn/Out`, `SignInButton/SignUpButton` backed by
  Better Auth, so ~20 callsites only needed their import path swapped.
- `components/convex-client-provider.tsx` — `ConvexProviderWithClerk` →
  `ConvexBetterAuthProvider`.
- `app/layout.tsx` — dropped `ClerkProvider`; re-enabled `AuthSync`.
- `middleware.ts` — Clerk middleware → a default-deny session-cookie redirect
  gate (real authorization is enforced in the Convex functions).
- `app/api/auth/[...all]/route.ts` (new) — Better Auth ↔ Convex request proxy.
- `app/sign-in` / `app/sign-up` — Clerk `<SignIn>`/`<SignUp>` replaced with
  Better Auth email/password + social forms. Deleted the Clerk `sso-callback`.
- `@clerk/nextjs` and `@clerk/themes` removed from `package.json`.

## Why `identity.subject` still works everywhere

Convex functions authorize via `ctx.auth.getUserIdentity().subject`. Under Better
Auth that subject is the Better Auth user id (it was the Clerk id before). The
app looks users up by `users.clerkId === identity.subject` (index `by_clerk_id`)
in ~170 places — none of those changed, because the *field* still holds "whatever
the current auth subject is." Only the value's origin changed.

## Existing-user reconciliation (READ THIS if you have real users)

Better Auth assigns brand-new subject ids, so a returning user would otherwise be
orphaned from all their data. On first Better Auth login, `AuthSync` calls
`createOrUpdateUser`, which:

1. looks for a `users` row already linked to the new subject — if found, done;
2. otherwise looks up a **legacy row by email** (`by_email`); if found with a
   different `clerkId`, it **relinks** that row to the new subject and re-keys the
   subject-keyed tables via `rekeyAuthSubject`:
   `leagueMemberships`, `teamClaims`, `stripePayments`, `creditTransactions`,
   `userCredits`;
3. otherwise creates a fresh user row.

Tables whose `userId` is `v.id("users")` (comment conversations/responses,
notifications, email logs) reference the stable `users._id` and need no change.
**`managerActivity`** stores a raw subject but has no `by_user` index, so it is
**not** re-keyed automatically — re-key it with a one-off migration if you use it.

⚠️ This path is guarded and idempotent, but it was **not runtime-tested**. If you
have production users, **run it against a copy of your data first** and confirm a
migrated user keeps their leagues and credit balance before pointing real traffic
at it. It only reconciles on an exact email match; users whose Clerk email
differs from what they sign in with under Better Auth will get a new empty
account instead.
